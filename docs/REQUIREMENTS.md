# AI Music Studio 需求说明

> 文档版本：v0.1（第一阶段规划稿）
> 更新日期：2026-10-20
> 说明：带有 `依赖能力` 的需求，其实现方式取决于 [API_CAPABILITY_PLAN.md](./API_CAPABILITY_PLAN.md) 中对应编号（C01-C14）的验证结论。在验证通过前，这些需求只能按"降级方案"实现，或暂不实现。

## 1. 需求编号约定

| 前缀 | 模块 |
| --- | --- |
| FR-PRJ | 项目管理 |
| FR-GEN | 文字创作歌曲 |
| FR-HUM | 哼唱输入与哼唱成曲 |
| FR-EDIT | 局部旋律替换 |
| FR-VER | 版本管理 |
| FR-JOB | 生成任务管理 |
| NFR | 非功能需求 |

优先级：`P0` 必须有，`P1` 应该有，`P2` 可以晚做。

## 2. 功能需求

### 2.1 项目管理（FR-PRJ）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-PRJ-01 | 新建项目，填写名称；自动记录创建时间 | P0 | 新建后在项目列表可见，名称与创建时间正确 |
| FR-PRJ-02 | 项目列表：按更新时间排序，显示名称、选定版本、版本数 | P0 | 列表数据与数据库一致 |
| FR-PRJ-03 | 重命名、归档项目（归档不删除文件） | P1 | 归档后默认列表不显示，可在"已归档"中找回 |
| FR-PRJ-04 | 项目内保存歌词草稿和创作提示词（风格、情绪、演唱方式、乐器、自由描述） | P0 | 刷新页面后内容保留；每次生成时保存一份快照 |
| FR-PRJ-05 | 导入已有歌曲音频（mp3/wav/m4a/flac）作为项目的初始版本 | P0 | 导入后生成 `import` 类型版本，原文件保存一份且不被修改 |
| FR-PRJ-06 | 删除项目需二次确认，默认移入本地回收目录而非立即删除 | P2 | 误删可从回收目录恢复 |

### 2.2 文字创作歌曲（FR-GEN）

| 编号 | 需求 | 优先级 | 依赖能力 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-GEN-01 | 输入歌词、主题、风格、情绪、演唱方式、乐器偏好、自然语言要求，提交生成 | P0 | C01-C04 | 表单经 Zod 校验；提交后创建任务并立即返回任务 ID |
| FR-GEN-02 | 支持纯音乐（无人声）选项 | P1 | C03 | FluxPort 无独立字段，只能写入文字描述；界面注明"不保证无人声" |
| FR-GEN-08 | 支持目标时长，最长 5 分钟；可选择模型（`suno`、`Lyria-3.5音频音乐`、`Lyria-3pro音频音乐`） | P0 | C15 | 目标时长写入提示词；结果显示实际时长；当所选模型标称上限低于目标时长时提示（Lyria 3 Pro 约 3 分钟）。时长不可通过参数精确控制，界面不承诺达到目标时长 |
| FR-GEN-03 | 生成完成后自动下载音频到本地，并作为候选版本展示 | P0 | C03、C05 | 候选可离线播放；远端 URL 过期后仍可播放 |
| FR-GEN-04 | 多候选并排试听与比较（同一任务返回的多首、不同任务的结果） | P0 | C03 | 可切换播放，显示每个候选的参数摘要 |
| FR-GEN-05 | 基于某次生成的参数一键"重新生成"，可修改后再提交 | P0 | C03 | 新任务参数可追溯到来源任务 |
| FR-GEN-06 | 提交前显示预计费用或调用次数提示 | P1 | C14 | 若 C14 未能获得价格信息，显示"费用未知"而非估算值 |
| FR-GEN-07 | AI 辅助生成歌词 | P2 | 待查（Provider 是否提供歌词接口，或使用对话模型） | 生成的歌词可编辑后再用于歌曲生成 |

### 2.3 哼唱输入与哼唱成曲（FR-HUM）

| 编号 | 需求 | 优先级 | 依赖能力 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-HUM-01 | 浏览器麦克风录音：开始、暂停、停止、重录，实时波形 | P0 | 无 | 录音结果可回放，保存为 `hum` 类型资产 |
| FR-HUM-02 | 上传哼唱音频文件（wav/mp3/m4a/webm/ogg） | P0 | 无 | 上传后统一转换为标准格式（见 NFR-AUD） |
| FR-HUM-03 | 哼唱预处理：裁剪首尾静音、响度归一化，可选降噪 | P1 | 无 | 处理后的文件另存，原始文件保留 |
| FR-HUM-04 | 显示哼唱的音高曲线（f0）与估计速度（BPM），供用户确认旋律被正确识别 | P1 | 无 | 音高曲线与哼唱对齐显示 |
| FR-HUM-05 | 以哼唱为条件生成完整歌曲，同时输入歌词和风格 | P0 | C06、C07 | 仅当 C07 判定"哼唱旋律被遵循"时，结果标记为 `API 原生`；否则按降级路线并如实标注 |
| FR-HUM-06 | 结果页提供"原哼唱 / 生成结果"对照试听 | P0 | 无 | 两段音频可同步或切换播放 |
| FR-HUM-07 | 显示旋律遵循度参考指标（见 IMPLEMENTATION_ROADMAP 测试策略） | P2 | 无 | 指标仅作参考，界面注明计算方式 |
| FR-HUM-08 | 可选：将哼唱转换为 MIDI 并合成干净的引导旋律，作为生成条件 | P1 | C06、C07 | 用户可试听引导旋律并选择用原始哼唱还是引导旋律 |

### 2.4 局部旋律替换（FR-EDIT）

| 编号 | 需求 | 优先级 | 依赖能力 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-EDIT-01 | 选择项目内任一版本或导入的歌曲作为编辑基础 | P0 | 无 | 基础版本 ID 被记录 |
| FR-EDIT-02 | 波形时间轴上拖拽选择起止时间，支持数值微调与吸附到节拍 | P0 | 无（节拍检测为本地处理） | 起止时间精度至少 10 ms；吸附节拍可开关 |
| FR-EDIT-03 | 为选定区间录制或上传新的哼唱 | P0 | 无 | 哼唱资产与本次编辑关联 |
| FR-EDIT-04 | 填写修改要求（新歌词、风格变化等自然语言） | P0 | 无 | 随编辑记录保存 |
| FR-EDIT-05 | 执行局部重创作，系统根据能力自动选择策略，并在提交前告知用户策略及其限制 | P0 | C09、C10、C11 | 界面明确显示策略名称与"API 原生 / 本地处理 / 降级方案"标签 |
| FR-EDIT-06 | 结果与原曲 A/B 对比：整曲对比、仅区间对比、区间前后各数秒的衔接试听 | P0 | 无 | 可一键切换 A/B，播放位置保持一致 |
| FR-EDIT-07 | 用户确认后另存为新版本；不确认则仅保留为候选，不影响原版本 | P0 | 无 | 原版本音频文件哈希不变 |
| FR-EDIT-08 | 最终版本中，选定区间以外的音频与原曲保持一致（逐样本或在允许误差内） | P0 | 本地拼接引擎 | 自动化"空测试"通过（见 IMPLEMENTATION_ROADMAP） |
| FR-EDIT-09 | 衔接处无明显爆音、断拍；交叉淡化时长可调 | P0 | 本地拼接引擎 | 衔接点无削波；节拍偏差在阈值内 |
| FR-EDIT-10 | 区间过短或过长时给出提示（具体阈值依 C09 结论设定） | P1 | C09 | 阈值来自验证记录，而不是硬编码猜测值 |

### 2.5 版本管理（FR-VER）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-VER-01 | 每次生成或编辑产生的音频都保存为版本（候选或正式），永不覆盖 | P0 | 文件以内容哈希校验，任何版本的文件都不被改写 |
| FR-VER-02 | 版本记录：来源类型、父版本、使用的 Provider、模型、参数快照、提示词与歌词快照、实现方式标签 | P0 | 版本详情页可查看全部字段 |
| FR-VER-03 | 局部编辑版本额外记录：起止时间、哼唱资产、修改要求、所用策略、交叉淡化参数 | P0 | 字段完整 |
| FR-VER-04 | 设置/切换项目的"选定版本" | P0 | 同一项目同一时刻只有一个选定版本 |
| FR-VER-05 | 版本历史列表与父子关系展示（第一版列表即可，树状视图放到后期） | P0 | 能看出每个版本由哪个版本派生 |
| FR-VER-06 | 导出某个版本音频（原格式或 wav） | P1 | 导出文件可正常播放 |

### 2.6 生成任务管理（FR-JOB）

| 编号 | 需求 | 优先级 | 依赖能力 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-JOB-01 | 所有远程生成都以异步任务执行，状态：`queued` / `submitting` / `running` / `downloading` / `succeeded` / `failed` / `cancelled` | P0 | C04 | 状态转换符合状态机定义 |
| FR-JOB-02 | 记录 Provider 任务 ID、提交时间、完成时间、错误码、错误信息、重试次数 | P0 | C04 | 失败任务可在界面查看原因 |
| FR-JOB-03 | 应用或 worker 重启后，未完成任务能恢复轮询，不重复提交 | P0 | C04 | 重启测试通过；已有 Provider 任务 ID 的任务不会再次提交 |
| FR-JOB-04 | 失败重试：仅对可重试错误（网络、超时、5xx）自动重试，带退避；扣费类操作重试前需确认未成功提交 | P0 | C14 | 不因重试产生重复扣费 |
| FR-JOB-05 | 任务列表页与项目内任务进度提示 | P1 | 无 | 状态实时更新（轮询即可） |
| FR-JOB-06 | 并发限制：同时运行的远程任务数可配置 | P1 | C14 | 超出时排队 |

## 3. 非功能需求

### 3.1 安全（NFR-SEC）

| 编号 | 需求 |
| --- | --- |
| NFR-SEC-01 | API Key 只保存在服务端环境变量（`.env.local`），不进入浏览器、前端打包产物、日志和 Git 仓库 |
| NFR-SEC-02 | `.env.local`、`data/` 目录写入 `.gitignore`；仓库只提交 `.env.example`（仅占位符） |
| NFR-SEC-03 | 所有请求/响应日志经统一脱敏器处理，脱敏 `Authorization`、`x-api-key`、URL 中的签名参数 |
| NFR-SEC-04 | 本地服务默认只监听 `127.0.0.1`，不对局域网开放 |
| NFR-SEC-05 | 如需把本地音频临时暴露为公网 URL（见 C06），必须由用户显式开启，链接短时有效，并在界面提示隐私风险 |
| NFR-SEC-06 | 前端构建产物中不得出现 Key 字符串，作为自动化检查项 |

### 3.2 数据完整性（NFR-DATA）

| 编号 | 需求 |
| --- | --- |
| NFR-DATA-01 | 音频文件只追加不覆盖；每个资产记录 sha256，读取时可校验 |
| NFR-DATA-02 | 远程生成结果在任务成功后立即下载到本地，不依赖远端 URL 长期有效 |
| NFR-DATA-03 | 数据库与 `data/` 目录可整体复制备份；提供一键备份脚本（P1） |
| NFR-DATA-04 | 数据库变更通过 Prisma migration 管理 |

### 3.3 音频规范（NFR-AUD）

| 编号 | 需求 |
| --- | --- |
| NFR-AUD-01 | 内部处理标准格式：WAV PCM 16-bit 或 32-bit float，44.1 kHz，立体声（哼唱可单声道） |
| NFR-AUD-02 | 原始文件始终保留；转换结果作为派生资产保存 |
| NFR-AUD-03 | 所有拼接、裁剪在统一采样率下进行，避免重复有损编码 |
| NFR-AUD-04 | 输出不得出现削波（峰值不超过 0 dBFS），衔接点无可闻爆音 |

### 3.4 可靠性与性能（NFR-REL）

| 编号 | 需求 |
| --- | --- |
| NFR-REL-01 | 页面操作（非生成类）响应时间在本地应小于 500 ms |
| NFR-REL-02 | 波形加载 5 分钟歌曲应在 2 秒内完成（可预先生成波形峰值数据） |
| NFR-REL-03 | 外部 API 请求设置超时；轮询间隔遵循 Provider 建议（以 C04 结论为准） |
| NFR-REL-04 | 本地音频服务不可用时，界面给出明确提示，不影响项目浏览与试听 |

### 3.5 可维护性（NFR-MNT）

| 编号 | 需求 |
| --- | --- |
| NFR-MNT-01 | Provider 参数与响应结构只出现在 Adapter 内部，业务层与前端使用统一领域模型 |
| NFR-MNT-02 | 外部 API 请求与响应用 Zod 校验，结构变化时尽早报错 |
| NFR-MNT-03 | 提供 `MockProvider`，在无 Key、无网络时可完整开发与测试 |
| NFR-MNT-04 | 代码使用 TypeScript 严格模式；Python 服务使用类型标注 |

## 4. 异常场景

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| EX-01 | 未配置 API Key 或 Key 无效 | 生成按钮禁用，并提示在 `.env.local` 中配置；不发起请求 |
| EX-02 | Provider 返回余额不足、限流 | 任务标记失败并显示原因；限流类错误按退避重试 |
| EX-03 | 上传的歌曲被 Provider 以版权原因拒绝 | 显示原文错误，提示用户该文件不能用于远程处理；本地功能（试听、拼接）仍可用 |
| EX-04 | 任务长时间无结果 | 超过阈值标记为 `failed(timeout)`，保留 Provider 任务 ID，允许手动再次查询 |
| EX-05 | 结果 URL 下载失败或已过期 | 在有效期内自动重试下载；彻底失败则标记失败并记录 URL 与时间 |
| EX-06 | worker 在提交请求后、写入任务 ID 前崩溃 | 任务置为 `unknown_submission`，提示用户在 Provider 控制台核对，禁止自动重提 |
| EX-07 | 浏览器拒绝麦克风权限 | 显示授权指引，并提供上传文件的替代入口 |
| EX-08 | 浏览器录音为 webm/opus，Provider 不接受 | 由本地音频服务转换为 wav/mp3 后再上传 |
| EX-09 | 哼唱过短、过安静或几乎无音高 | 预处理阶段提示，并允许用户坚持提交 |
| EX-10 | 局部替换区间过短或越界 | 前端阻止提交并提示合法范围 |
| EX-11 | 新片段的速度或调性与原曲不一致 | 拼接前检测；超出可校正范围时提示用户，而不是强行拼接 |
| EX-12 | 磁盘空间不足 | 写文件前检查，失败时不留下半写入文件，并提示用户 |
| EX-13 | 本地音频服务未启动 | 依赖它的功能禁用并提示启动命令 |
| EX-14 | Provider 响应结构与预期不符 | Zod 校验失败，任务失败并保存脱敏后的原始响应供排查 |
